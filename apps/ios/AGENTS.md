# Bay for iPhone (native)

The native SwiftUI rewrite of `apps/mobile` (plan: `docs/mobile-native-plan.html`). Minimum iOS 15.0; Apple silicon simulators only.

- The Xcode project is generated by Tuist from `Project.swift` and isn't checked in: run `scripts/generate.sh` after changing targets or adding files (it builds the Rust core first, because the project lists the Swift API the core generates).
- Build: `xcodebuild -workspace Bay.xcworkspace -scheme Bay -destination 'generic/platform=iOS Simulator' -derivedDataPath build/DerivedData build`. The `BayCore` target runs `packages/mobile-core/scripts/build-ios.sh` first, which rebuilds the Rust core for the platform being built and regenerates its header and Swift API (rustup's cargo, not Homebrew's). A new Rust export is usable in one build.
- Words come from the core's catalog through `Strings` (`strings.t("key", ["name": value])`), never hard-coded text.
- Debug installs as `in.krishkalaria.bay.mobile.native`, beside the Expo app; Release uses the store ID.
- Drive the simulator with Argent (`reinstall-app` with the built `Bay.app`, then `launch-app`). Give every control an `accessibilityIdentifier` equal to the Expo app's `testID`, so the `.argent/e2e` flows keep working.
- The page engine is the `BayEngine` framework (`BayEngine/Sources`), ported from the Expo module (`apps/mobile/modules/bay-engine/ios`): `EngineView` (a `UIView` over `WKWebView`) reports everything through `onEvent` as one `EngineEvent` enum, and `Engine` holds what all views share (content blocking, private sessions, spaces' data, downloads, media, voice). It builds in Swift 5 mode; the app target is Swift 6 with complete concurrency checking. SwiftUI hosts a view through `EngineHost` (`Bay/Sources/EngineCheck.swift`, the debug screen behind "Engine check").
- The content blocker's C functions (`packages/adblock/include/bay_adblock.h`, module `BayAdblock`) come from the core's library: `build-ios.sh` builds `bay-core` with its `adblock` feature, so the app carries one Rust artifact (plan D16). Read release archives with rustup's `llvm-nm`; Xcode's `nm` can't read objects from a newer LLVM and shows nothing.
- The share extension (`BayShare`) and the search widgets (`BayWidgets`, iOS 18+) are Tuist targets embedded in the app, with sources from the Expo app's `share-extension` and `widget-extension`. Their bundle ids extend the app's per configuration (`BASE_BUNDLE_ID`). Both open `bay://` links, so the app declares the `bay` scheme.
