The gaps fall into four groups. Each needs different work:

  1. The ports are behind main. Main's file rename (b1ba0b2c) moved the directories that the ports add files to. Merge it first; every later item depends on it.
  2. Features that look present but do nothing. The UI shows the control, but the host never registers the method, so the call fails or quietly does nothing. Examples: download pause, resume and cancel; Boost export and import; Copy File; the font list. These are the most urgent because users can see them.
  3. Mac-only features with no port. These are whole modules: content blocker, permission and password prompts, local files, user scripts, the CLI installer, capture, Little Bay's hotkey, cast and device pickers.
  4. Gaps already decided as "drop" or "replace" in the Linux port plan: glass, Dock, menu bar, AppleScript, Handoff, Apple Translation and EventKit. They're listed only so they aren't mistaken for missed work.

Priority: native methods (section 2) and page events (section 3) come first, right after the merge with main, which they depend on. See the order of work.

Legend. Wire the engine or shared code already does it; only the host route is missing · Port needs a new implementation · Replace a different mechanism on Linux/Windows · Verify may already work through another route; confirm before writing code · Drop decided out of scope.

Known gaps in finished rows

What a Source-complete row still leaves open, kept with the code: each feature commit adds what it couldn't finish, and whichever commit closes a gap removes it. Nothing on this list blocks the row's main path.

  • Everything native: nothing has been compiled or run on Linux or Windows. Source is syntax-checked against Chromium 154 with a Mac config, the native tests are written but unrun, and Windows-only branches aren't checked at all.
  • Dev hooks: windowDrags and AppKit-only actions answer unsupported_action, so ported scripts must choose a replacement.
  • Icon fetch: SVG favicons return null.
  • Copy File: x-special/gnome-copied-files is written because Nemo, Thunar and Caja are expected to need it; try pasting in each. It goes through ScopedClipboardWriter::WriteRawDataForTest, the only writer that keeps the format's exact name; a small Chromium patch could add a properly named one.
  • Text file dialogs: Save starts in Downloads where macOS reopens the last folder. A second dialog while one is open rejects with dialog_busy, which the Boost code doesn't catch. A failed save tells nobody, as on macOS.
  • Ctrl‑Tab switcher: Ctrl+Tab no longer steps to the next tab as it does in Chrome; that's Ctrl+PageDown. If Ctrl comes up before focus reaches the document (a very quick tap from a page), the switcher commits on the next key or click instead. A click inside a page doesn't cancel it, because the page's events don't reach the document.
  • Clear animation: the canvas draws on the main thread, so a busy window may drop frames where Core Animation wouldn't.
  • Crash reports: minidumps carry no symbols, so a report has one frame (module and offset) where macOS's has the stack. They're empty unless the build runs Crashpad, which a non-branded Chromium build may not. Page and GPU process crashes aren't reported, as on macOS.
  • Intro music: the reverb is a generated impulse, close to but not AVAudioUnitReverb's large hall. devRenderIntroMusic (writing the piece to a file for videos) is macOS only.
  • Test harness hooks: devKeyEquivalent infers what fired from the window's key shortcuts rather than watching a menu fire, and ignores focus, settle and wait. devSnapshotWindow ignores transparent. The apps/browser/scripts/*-test.mjs suites still drive macOS with AppleScript and cliclick in places, so porting a suite means replacing those steps.
  • Tab drag previews: the card shows the page's own picture or the whole window, where macOS lays the page into the window's picture; the placeholder shows the title without the favicon. The card fades as soon as it reaches the new window rather than waiting for its content. Wayland has no preview at all, and X11 has none either while globalWindowCoordinates stays off on Linux.
  • Font list: the Boost font menu stops at 998 families, because host menus end at 1000 items.
  • Shortcuts: a key taken off its command is swallowed rather than reaching the page, as it does on macOS. The catalog lists macOS's whole menu, including modules not ported yet, so binding one of those may do little. previewTransport doesn't answer recordShortcut, so a field stays on "Type Shortcut" in the browser preview.
  • Little Bay global access: Bay only listens while it runs, and on Linux it quits with its last window, so neither the shortcut nor the tray icon can wake it the way macOS's stay-open app does. GNOME on Wayland gives Chromium no global shortcut listener, so Settings says "unavailable" there. Under the XDG portal the desktop picks the final key and never reports a clash. Without a StatusNotifierItem host (stock GNOME) the tray icon doesn't appear. Hiding and showing all Little Bays (macOS's Dock menu) has no equivalent, and Little Bay's put-away timer (startLittleBayPutAway) still doesn't start in the shared runtime, though Settings offers it.

6. Order of work

Native module progress, 3 Nov: profile cleanup, screen sharing, Chrome tab-strip mirroring and extension install prompts are implemented in the shared host source on feat/linux. The source checks and JavaScript tests run on this Mac; native tests are written for the Linux host target. Shared host code is copied to feat/windows as each feature lands; none of it has been run in the native Linux/Windows app yet.

Priority: native methods and page events first. The merge with main stays as step zero because it's a prerequisite: every method below lands in files that the rename moved, so doing it first avoids redoing work. After that, the native gaps from sections 2 and 3 come before anything else. As before, write and check code on the Mac, put shared host code on feat/windows and Linux-only code on feat/linux, and land each by merge.

  1. Step zero: sync with main

    Done on 3 Nov 2026: all nine local main commits are pushed through b5a6fbb1, and main is integrated into both feat/windows and feat/linux, with package moves, contracts and runtime commands reconciled. Counts elsewhere describe the original audit snapshot.

    • Done: push local main (9 perf commits).
    • Done: merge main → feat/windows, then resolve the moves in section 1.
    • Done for Linux: merge main → feat/linux directly. Merge future shared Windows changes into Linux as usual.
    • Regenerate contracts. Run the JS, platform and native runtime tests and both web exports.

    Done when both ports contain main and their tests pass at the same counts as before the merge.

  2. Native methods

    The first priority. Every Wire and Port row in section 2, in this order: what users already see failing first, then the engine, then shell and system, then whole modules.

    1. Wire: download pause, resume and cancel; copyFile, renameFile; saveTextFile, openTextFile; chooseImportFile and notification permission on Linux.

8. Open questions

  1. Translation. Keep it dropped, use Chrome's built-in translate, or reuse the Bergamot work parked on feat/mobile-translation? Bergamot would give the same feature on all three desktops.
  2. Calendar. Meeting alerts and the Live calendar are a large Mac feature (23 gated call sites). Is a Google Calendar or CalDAV source in scope for the ports, or does it stay Mac-only?
  3. DRM. Without WebKit, Netflix and other DRM sites have no engine on the ports. Should Chromium on both ports fetch the Widevine CDM through the component updater? Windows also needs Verified Media Path (VMP) signing before streaming services accept it.
  4. On-device AI. Tidy names and inline completion need Apple's model. Drop them, or pick a local model for the other platforms?
  5. Chrome's own prompts. For the P1 events, is Chrome's built-in bubble acceptable for a first beta, so Bay's prompts can follow later?

How this was measured

  • Methods: every method in packages/platform/src/nativeContracts.ts (23 modules, 309 methods) was checked against the feat/linux host sources in chrome/browser/bay/. The check excluded the generated native_contracts.g.h, tests, and the other platform's _win/_linux files and BUILDFLAG blocks. It also used the import and sync MethodNames() lists. A method counts as routed if the host names it. This is a text match, so it can miss a method that is built from strings at runtime; the Verify rows are where that's most likely.
  • Events: the on* props of WebViewProps were compared with the event names the host emits.
  • Merge: git merge-tree --write-tree origin/feat/linux main. Nothing was merged.
  • Side branches: every local t3/linux-* branch is already in feat/linux by patch. Only feat/linux-k-engine has one unmerged commit, a docs note.
