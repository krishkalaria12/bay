3. Adapt the runtime to the coordinator

Main's runtime is a module-level ManagedRuntime shared by windows in one JavaScript instance. Windows and Linux use separate WebUI documents. The new shared owner must be one app runtime per coordinator epoch. A renderer importing a command helper must not accidentally start persistence, sync or telemetry.

Coordinator owns application work

Writable authority store, persistence, history/bookmarks, sync/import, account polling, app listeners, native reconciliation and service state publication. The coordinator starts and stops their Effect scopes.

Windows own presentation

Read-only projections, input, animation and view-bound native operations. Shared mutations and async service requests travel through the authenticated command transport. Closing one window leaves shared services running.

  1. Preserve bootstrap ordering. Install native transport before importing app modules. Keep authenticated role selection and the existing startup path without a local-writer fallback. Restore disk only for a fresh epoch; recover accepted state for a replacement. Keep initial publication and command/close subscriptions ahead of service startup, and native page-fact startup after initial acceptance.
  2. Make runtime creation explicit. Refactor effect/runtime.ts to expose a runtime factory and keep macOS's existing single-instance entry. Give each coordinator owner a fresh layer memo map. Avoid runtime allocation or native service startup as a module import side effect.
  3. Inject the actual authority store. Add an app-local context port for BrowserStore and native adapters. Audit main's services for global useBrowser reads and writes. Supply the coordinator store; keep the store package and reducers free of Effect. Include module-level caches, mutable maps and Live/account state in this audit. Prove isolation with two independently constructed authority stores in one test process, rather than repeatedly testing the imported singleton.
  4. Keep command authorization and ordering. Call programs from runtime/serviceExecutor.ts after existing validation. Preserve epoch/revision checks, duplicate request handling, publication before acknowledgement, private-profile projection and page-fact ownership. UI callers receive serializable results, never Effect values or fibers. Preserve service-state filtering so credentials and private data cannot enter a projection. Disconnected windows remain read-only.
  5. Keep Undo in the originating command. The authority currently runs initial service reducers synchronously before the first await. Effect execution may defer that work. Retain a synchronous validation/reducer step inside the existing authority queue, then owned async work and an ordered completion. Test Undo attribution and that a slow service command leaves ordinary reducer commands free to run. Avoid a second queue that changes this ordering.
  6. Keep native calls honest. Map transport rejection, native domain failure, cancellation, missing optional methods and permission denial separately. Reuse the versioned Mojo contracts. Scope subscriptions and timers in the app; keep the raw transports and package APIs as Promise/callback APIs.
  7. Define interruption per operation. Abort cancellable reads and polls; guard late callbacks with the current epoch and resource identity. A JS interruption does not cancel a native write. Track accepted mutations to settlement before releasing locks or replying to quit. Never retry a non-idempotent mutation blindly. The current native invoke transport has no cancellation signal. Do not claim wrapping it in Effect makes the native operation cancellable.
  8. Close the owner cleanly. Failed layer acquisition, disconnect and coordinator replacement release already acquired resources. Adapt the current synchronous dispose() hooks to tracked asynchronous finalization where needed. Cancelled quit resumes the existing owner; it must not dispose it. Invalidate the epoch and stop accepting work synchronously, then expose a tracked teardown promise for tests and controlled restarts to await. Page unload cannot guarantee asynchronous finalizers finish.

The highest-risk merge is lib/persistenceService.ts together with lib/shellBridge.ts. Main's synchronous flush cannot replace WebUI's disk-acknowledged flush. Keep session, downloads and Live writes ordered and awaited before the native quit reply, including quit cancellation and stale callbacks.

Keep Effect at 4.1.3 for this integration. Only apps/browser and apps/cli depend on it. packages/platform, desktop, chromium, import, sync and core stay Effect-free. The browser uses core Effect only, preserving the macOS Hermes bundle; the CLI alone uses the Bun platform package. Native C++, Swift, Rust and PowerShell retain their existing roles.

4. Windows branch work

Target: feat/windows · shared integration owner first, then Windows native acceptance.

W1 / merge and contracts

Combine main with the Windows host

Resolve the common conflicts, retain index.web.ts role selection, @bay/platform, web Metro resolution, native contracts, engine call generation and the Windows workflow scripts. Merge the standalone CLI rewrite with Windows endpoint and bundling fixes.

Exit: manifests and lockfiles agree; native contract generation is current; desktop and web type checks pass. New Effect imports resolve in both the macOS and WebUI bundles.

W2 / ownership and durable writes

Attach Effect to the authority lifetime

Implement the runtime factory and authority-store port. Move startCoordinatorServices, service commands, sync, extensions, telemetry and app lifecycle into one supervised owner. Keep service-state projections and async flush/resume/dispose behavior. Confirm window bundles cannot acquire the application runtime through transitive imports.

Exit: a two-window test observes one persistence subscription, sync owner and poller. Window closure leaves them alive; coordinator disposal removes them. Quit waits for writes; cancelling quit resumes saving.

W3 / workflow conversion

Complete the shared workflow ledger

Apply every inventory row above. Preserve DPAPI/NSS import behavior, explicit guidance for app-bound secrets, native notification routing, Windows file dialogs, default-browser registration and signed updater behavior. Add app-local Effect adapters around the existing native APIs where needed.

Exit: no duplicate legacy worker remains; service tests cover typed failure, interruption and late native replies. Renderer actions still pass through the existing command validation.

W4 / target OS and installer

Prove it in the packaged Windows app

Run Windows checks, build the pinned engine, run native runtime tests and the hosting gate. Verify two-window editing, private isolation, tab transfer, restore, shutdown and recovery. Exercise DPI changes, Snap, IME, accessibility, media/PiP, clipboard, notifications and installer/update cancellation. Keep the compressed installer and runtime resource set.

Exit: record a Windows integration SHA with portable checks, actual Windows build/runtime results and installer evidence. Only then carry this shared integration into Linux.

5. Linux branch work

Target: feat/linux · depends on the recorded Windows integration SHA.

L1 / carry the shared integration

Merge Windows into Linux and retain Linux's delta

Bring in the Windows integration, then review every Linux-only override. Preserve Expo Image and its macOS/native patches, Linux capabilities, engine routing, Nix packaging and the Linux CI fixes. Resolve dependencies with both the image work and Effect present.

Exit: the chosen main SHA is an ancestor; Linux's platform methods and image work remain. Common service suites, web boot, web types and production export pass on the merged Linux tree.

L2 / native adapters

Bind Linux operations to the same Effect services

Use the shared coordinator runtime and workflow layers. Map Linux-specific method support, failures and permissions at app adapters. Preserve libsecret storage, native import/crypto, autostart/default-browser actions, portal/file dialog behavior and notification activation. A missing service or denied permission must stay distinguishable from success.

Native anchors: webui/{app_services_linux,secret_storage_linux,autostart_linux,sync_ui_linux}.cc, keychain_linux.cc, shell_files.cc, shell_clipboard.cc; portable packages packages/import/linux and packages/sync/linux.

Exit: supported, denied, unavailable and disconnected cases have tests. Account or secret callbacks after disposal cannot write to a new epoch. The full shared workflow ledger is complete on Linux too.

L3 / compositor and lifecycle

Run the real host on Wayland and X11

Validate SurfaceEmbed with the merged runtime before accepting Linux. Exercise two-window state changes, split/peek pages, tab tear-off and adoption, parked pages, fullscreen/PiP, DevTools, focus, IME, scale changes and clipboard/drag-and-drop. Cover GNOME and KDE where the existing Linux plan requires their different integration paths.

Repeat restore, quit/cancel, coordinator replacement, secret-service denial, notification click and file-picker cancellation. Check the Expo Image change on WebUI and the retained macOS host.

Exit: native rendering and input work under both display protocols; epoch and profile ownership hold during window churn. Report failures by tested desktop/session rather than treating one distro boot as general Linux acceptance.

L4 / build and package

Build and validate Linux distribution artifacts

Use the Linux engine driver and pinned sysroot. Build the app, run import/sync/native tests and validate the existing tar/deb/rpm packaging paths. Check the Nix package separately if shipping it. Verify desktop entry/default-browser integration, sandbox status, shared libraries, locales, codecs and GPU fallbacks from the staged artifact.

Exit: each advertised package has install/launch evidence, session persistence and native smoke results. Unsupported architectures or distributions stay outside the tested claim.
