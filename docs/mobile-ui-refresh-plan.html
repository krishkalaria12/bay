Site search, a lighter bar and menu, saving bookmarks to folders, a bookmarks drawer, and per-site fonts

The reference video walks through one flow: search a site from the address field, open the page, save it to a folder in a space, browse that space's bookmarks in a drawer, then search Wikipedia and give the site its own font. This plan breaks that flow into features, notes which parts Bay already has, and orders the work so every round ships on both iPhone and Android together.

Not in scope: summaries. At 9–12 s the video summarises the page with on-device AI (the card shrinking into a "Summary" sheet). It's left out, along with the fourth bar button that opens it (the one that shows up once a page loads).

1 · The search sheet

1a · The page stays still, blurred behind the sheet new

When search opens over a page, the page stays exactly where it is, blurred and a little dimmed behind the sheet. (A first try shrank it into a card above the sheet; it moved the page out of place, so it's gone.)

  • iPhone: a thin material over the page, which blurs WebKit's view where it stands.
  • Android: our Chromium draws on a SurfaceView that no blur in the app reaches, so search takes a fresh picture of the page and draws it blurred in the same place. Private tabs keep no picture, so they're dimmed only; so is everything before Android 12.

1b · Light or dark to match the page new

Over a dark page (IMDb at 20 s) the sheet goes dark. Today only private search is dark. Decide from how bright the sampled top colour is, and keep the private look as it is.

1c · Site shortcuts under the empty field new

A row of up to five site icons shows before anything is typed. Tapping one starts searching that site (section 2). Pressing and holding one opens the site itself.

  • Which sites (the core picks, nothing to set up): the space's pinned sites that have a site search first, then the sites with a search that get visited most. Editing the row can come later (D4).
  • Recent pages still show under the row.

1d · Bookmark rows say where they're saved new

A row that's a bookmark shows its space and folder under the title ("Personal · Watchlist") with a small bookmark icon, instead of the address. That means a new location field on Suggestion::Page, filled in by search_field.rs from the bookmark tree.

Search looks through bookmarks in every space (D2): the current space's come first, and other spaces' rows show their space name. Opening one from another space switches to that space and opens it there.

2 · Site search and bangs

2a · Recognising a site port

Port findScope to a new input/site_search.rs. It should check the same things in the same order as desktop: a custom engine's keyword, then built-in engines (host, keyword or name with 3+ letters), then POPULAR_SITE_SEARCHES (keyword, host, or name), then any host in the space's history (which searches the default engine with site:). Bring the desktop tests over as fixtures in tests/input_fixtures.rs so both sides behave the same.

  • When the typed text matches a site, the first row is Search IMDb with the site's icon (a new Suggestion::Scope). Bookmarks and history for that host follow, as in the video.
  • Tapping that row, or typing a space or Tab after an exact keyword ("w␣"), turns the field into the chip.

2b · The chip new

  • Inside the field, on the left: the site's icon and name. The placeholder changes to "Search IMDb". The field takes the site's colour, bright for a moment and then settling to a light tint (1.5 s → 2 s in the video). Pick text colour by contrast; the desktop's isLightColor does the same job.
  • Backspace on an empty field removes the chip. The clear button clears the text first, then the chip.
  • Colours: port SITE_COLORS into the core (add IMDb #F5C518; Wikipedia's chip is white in the video). With no entry, use the site's theme colour from the favicon store if there is one, otherwise the plain fill.
  • Going: scopedSearchUrl. Engine and site scopes fill their %s; history scopes search the default engine with site:host.

2c · Bangs port

  • Port the parsing in bangs.ts (!w font, font !w, keeping the search on the bang's own site with staysOnSite) to input/bangs.rs.
  • Bundle the trimmed list as packages/mobile-core/data/bangs.txt, made from bangList.ts by a script beside the emoji and units ones. Read it lazily on first use so starting the app doesn't pay for it.
  • Refresh like desktop does: the core keeps bangs.txt and its ETag in its own data folder and checks once a day through the app's HttpClient, without cookies.
  • Typing !yt␣ turns into the YouTube chip, so bangs and site names end up in the same state.

2d · The site's own results new

Inside a scope, the rows are the typed text first, then results from the site itself: IMDb titles with poster, year and cast; Wikipedia articles that open the article directly ("Font" goes to /wiki/Font, not a search page). This is a new kind of row: Suggestion::Result { title, detail, image, url }.

Site Where results come from Row
IMDb v3.sg.media-imdb.com/suggestion/x/{q}.json poster · title · "year · cast" → title page
Wikipedia {lang}.wikipedia.org/w/api.php?action=opensearch (or REST with thumbnails) article title → article
YouTube suggestqueries.google.com/complete/search?client=youtube&ds=yt search text → results
Everything else the default engine's suggestions with nothing added search text
  • The core builds each request and reads each answer (scope_suggest_request, parse_scope_suggestions). The apps only do the network call, using the same wait-after-typing and keep-the-latest logic RemoteSuggestions uses now.
  • Posters load through the app's image loader and are kept in memory only. Follow searchSuggestions: if it's off, don't ask sites for results either.

No fourth button: a Bookmarks button was tried and taken out (D1). The address capsule leaves the bar and moves to the top of the menu (section 4). The start page bar stays as it is.

  • Keep in BrowserBar: sliding sideways to change tabs, the loading line (draw it on the search button), the tab count, and hiding the bar on scroll.
  • A page that isn't secure needs another place to say so now that the address is gone. A small mark on the search button, plus the menu's address row, will do.
  • Opening search from the bar still starts with the page's address filled in and selected.

4b · One sheet style for every Bay sheet

Every sheet in Bay (the page menu, site settings, the Tabs menu, history, downloads, Reader, the space editor, and the rest) takes the page menu's look from the reference: a card that floats over the page, with no ✕. You close a sheet by tapping outside it, dragging it down, or with Back on Android and the escape gesture with VoiceOver.

  • Each platform's own sheet. iPhone follows the reference: the system sheet, floating as glass on iOS 26, which keeps the system's drag, keyboard and VoiceOver handling, with rows on rounded cards. Android follows Android: a bottom sheet along the screen's edge with its top corners rounded and a drag handle, flat rows, sections split by a full-width line, no outlines or shadows. (Imitating iPhone's glass on Android was tried and looked wrong.) Sheets stand no taller than about 62% of the screen and scroll.
  • The top: a small title, centred. A sheet one level down (site settings, a font list) has a round back button on the left, and its title is what it's about (en.wikipedia.org, Font). The page menu's top is the address row instead of a title. A form (the bookmark sheet) has a round ✕ to cancel on the left and a round ✓ to save on the right, because there closing and saving are different things.
  • The rows: on iPhone, grouped on rounded cards with hairlines between them; on Android, flat. A row that opens a list shows ⌃⌄ (Show Reader, Translate Page); a row that opens a page shows ›.
  • The address (page menu, site settings): one capsule with the lock and the address, cut short at the end, never wrapped. In the page menu, back and forward sit at its left and copy and reload at its right.

Built in PanelSheet (BayDesign/Sheets.swift, bay.design/Sheets.kt), so all 22 sheets change together. The *-close buttons go, so the tests that tap them close by dragging down or Back instead.

5 · Saving a bookmark to a space and folder

  • Top: ✕, "Bookmark", ✓.
  • Title (editable, with the site's icon) and the address (editable).
  • Space chips (SpaceChips, section 6b): the one chosen shows its glyph and name, the others just the glyph, then + for a new space. The current space is chosen at first.
  • Folders of that space: "Top of the List" (the top level), then each folder, nested ones indented, with a tick on the choice. Add a "New Folder" row at the end. Start with the last folder used in that space.
  • If the page is already saved, the sheet opens with where it is now. ✓ moves or renames it, and a Remove row takes it out.
  • After ✓: a toast at the top of the screen, "Added to Watchlist". Tapping it opens the drawer on that folder.

The core needs

  • New actions SaveBookmark { space_id, parent_id, title, url }, MoveBookmark { space_id, id, parent_id, index }, UpdateBookmark { space_id, id, title, url } and NewBookmarkFolder { space_id, parent_id, title }. Today there's only AddBookmarks, RemoveBookmark and ToggleBookmark.
  • Every new action has to go through the phone sync adapters (sync/phone/adapters.rs) so moves and renames reach the desktop as edits, not as a delete plus an add.
  • Remember the last folder for each space (preferences.last_bookmark_folder).
  • A query bookmark_location(url) giving space, folder and id. The save sheet, the Save tile's state and the rows in 1d all use it.

6 · The bookmarks drawer

A panel the full height of the screen that slides in from the right. The page slides left with a sliver still showing. Its background is a gradient in the space's colour (Personal red, Work blue, Reading green). A Bookmarks row in the page menu opens it, and so does tapping the "Added to …" notice, which opens it on that folder (D1). There's no edge swipe, so swipe-to-go-forward keeps working.

  • Top: space chips, the current one with its glyph and name. Swiping sideways over the list moves to the next space, and the tint fades from one colour to the next. This switches the browser to that space too, and the page sliver changes to that space's last tab (D3, section 6c).
  • List: the space's bookmarks as a tree. A folder opens and closes where it sits (Watchlist is open in the video); a closed folder shows its count and ›. Top-level links come last. The current page's row is highlighted.
  • + at the bottom right: save this page here, or make a new folder.
  • Hold a row to rename, move, share or remove it. Hold and drag to reorder (uses MoveBookmark).
  • Close it by swiping right, tapping the page sliver, or opening a bookmark.
  • This replaces BookmarksPanel. Bring over its search (a field that appears when you pull down on the list) and the Import row.
  • VoiceOver/TalkBack: folders are buttons that say whether they're open; announce the space when it changes.

Build from SpacesCapsule/SpaceGlyph, spaceColor, the swiping between spaces in TabSwitcher, and the core's bookmark tree. The core should hand over the tree flattened, with each row's depth and whether it's open, so neither app has to walk it.

6b · Spaces in the drawer and the save sheet

In the video, spaces are what hold everything together. Each space has its own bookmarks, its own colour and its own chip, and the same row of chips appears in two places: the top of the drawer (15–19 s) and the save sheet (13.5 s). Bay already has spaces with colours, glyphs and their own bookmarks (BrowserSpace, spaceColor, SpaceGlyph, SpacesCapsule), so the work is a new shared chip row plus the colour wash.

One SpaceChips component, used in both places new

  • The space chosen is a capsule filled with the space's colour, showing its glyph and name in white ("Personal" in red, "Reading" in green).
  • The others are just their glyph, on a rounded square with a darker shade of their colour (blue for Work, green for Reading). Tapping one chooses it. When the choice changes, the capsule moves from one chip to the next with the settle spring, and the old one shrinks back to a glyph.
  • + comes after the chips in the save sheet. It opens SpaceEditPanel to make a new space, then chooses the new space when you're done. The drawer gets its + at the bottom right (section 6).
  • When the chips don't fit, the row scrolls sideways and keeps the chosen chip in view. VoiceOver/TalkBack reads each chip as a button with the space name, and marks the chosen one as selected.
  • Glyphs: the space's emoji, or its first letter, exactly as now. The video's symbols (a person, a briefcase, a book) are close to 👤 💼 📖, and emoji keeps the glyph syncing with desktop unchanged. Suggest those three emoji when someone makes a new space.

The colour wash new

  • The drawer's background is a gradient from the space's colour (about 35% at the top, fading to near black at the bottom), over the dark glass. Personal is red, Work blue, Reading green: the existing SpaceColor set (gray, blue, green, orange, red, violet), so nothing new is needed in the core.
  • While you swipe between spaces, the wash blends between the two colours as your finger moves, not only once the swipe finishes. With Reduce Motion on, it fades instead.
  • The save sheet doesn't take the wash. Only its chosen chip shows the colour, so the sheet stays easy to read.

How choosing a space behaves

6c · Switching spaces from a page

How it works today

Way Steps from a page What's wrong
Swipe up on the bar → tab view → tap a space in SpacesCapsule 2 Goes through the whole tab grid just to change space.
Tab view → swipe sideways on the grid (TabSwitcher.spaceSwipe) 2 Doesn't follow your finger: the grid shifts 35%, then the new space's content just appears. You never see the next space coming. Desktop's spaces/pager.ts keeps the neighbouring spaces ready and follows the fingers.
Tab view → hold the capsule and slide (SpacesCapsule.scrub) 2 The nicest gesture there is (you asked for it on 2026-11-17), but it only exists in the tab view.
Hold Tabs → Tabs menu → Spaces list 2 + a sheet A list of names in a sheet, with no colour or glyph.

Also, nothing on a page says which space you're in. Since each space has its own website data (logins, cookies), not knowing which space you're in is a real problem, not just a looks problem.

What to build

  1. Hold Tabs, slide, lift: one gesture from any page. The same hold-and-slide you already use on the capsule, moved onto the button your thumb rests on.

    • Holding Tabs (0.35 s, with a tick) stands a column of the spaces straight up from the button, the nearest space at the bottom and + New space on top, so the thumb slides straight up. The space you're in sits on a soft grey circle. The one under the finger grows on a wash of its own colour, with its name in a pill over the column, and ticks. Lift on it to switch. (A row across the bar came first; a column over the button was the better reach.)
    • Lift without sliding, or slide back onto Tabs, and nothing changes. The Tabs menu sheet is gone; holding Tabs only ever shows the column.
    • With only one space, the column holds that space and + New space, so the hold always does the same thing.

  2. Say which space you're in. After a switch, a pill at the top shows the glyph and name ("💼 Work") for about 1.4 s, in the same place as "Added to Watchlist", and the Tabs button reads "Tabs, in Work" to VoiceOver and TalkBack. No ring on the button: a coloured ring read as a stray focus ring, so it was taken out. The new page sliding in from the side the space sits on is still to do.

  3. Make the tab view's sideways swipe follow your finger. Show the spaces either side of the current one, next to it, so the grid moves with your finger and the wash blends between the two colours. It stretches a little at the first and last space, and the chips at the bottom move along with the swipe. Draw the neighbouring spaces from their saved tab pictures, not live pages, to keep memory down.

  4. One set of chips everywhere. SpaceChips replaces SpacesCapsule's dots and the Tabs menu's plain list, so the colour, glyph and order look the same in the bar, the tab view, the drawer and the save sheet.

Ruled out

  • Swiping sideways on the bar: that already changes tabs, and should stay that way.
  • Swiping in from the screen edge: clashes with swiping back and forward (swipe-to-navigate).
  • A fifth bar button for spaces: the bar is full now that it has Bookmarks; the Tabs button already belongs with spaces.
  • Spaces in the page menu: too far down for something you do often.

Accessibility

  • VoiceOver and TalkBack can't do hold-and-slide, so the Tabs button gets custom actions ("Switch to Work", "Switch to Reading", "New space") through accessibilityActions on iOS and customActions semantics on Android. The button reads out the current space: "Tabs, 4 open, in Work".
  • The pill after a switch is announced.

The core doesn't change: SelectSpace already brings back each space's last tab (active_tab_ids) or makes a blank one. This is desktop's way of switching spaces, adapted to the thumb.

Fonts: Bay ships its own, the same on both apps

Bay bundles one set of fonts in both apps, so a site set to a font looks the same on iPhone and Android, and the setting means the same thing when it syncs (D5). New York, San Francisco and Georgia can't go in the Android app (Apple's and Microsoft's licences don't allow it), so the bundled set uses openly licensed fonts (SIL Open Font License) that fill the same roles as the video's list:

In the list Bundled font Fills the role of (video)
Same as All Websites — the default; follows the font set for all websites
Original Font — the site's own font, nothing changed
System not bundled: SF on iPhone, Roboto on Android San Francisco (System)
Literata Literata (variable, OFL) New York: a serif made for long reading
Inter Inter (variable, OFL) a neutral sans that looks the same on both
Nunito Nunito (variable, OFL) SF Rounded
Charis Charis SIL (OFL, based on Charter) Charter
Lora Lora (variable, OFL) Georgia: a warm serif for the screen
  • Size: each font cut down to Latin, Latin Extended, Greek and Cyrillic, as woff2 (variable where there is one), about 1.5–2.5 MB for the set. Other scripts (Hindi, Japanese) keep the system font by naming it next in the stack: font-family: "Bay Literata", system-ui. Fonts go in packages/mobile-core/design/fonts/ with a script that cuts them down, and both apps copy them in at build time. Their licence files go in the app's notices.
  • Settings: the font for all websites goes in Settings ▸ Browsing. Per site is SiteSetting.font: Option<SiteFont>, and the global one is preferences.site_font. SiteFont is an id in the core (System | Literata | Inter | Nunito | Charis | Lora), so it syncs and reads the same everywhere. Each font row in the picker is drawn in its own font.
  • Applying it: a page script (apps/mobile/src/pagescripts/tweaks.ts → pagescripts.json) adds one style rule setting font-family on text, and leaves out code, pre, kbd, samp, icon fonts (fonts named like icon/symbol, or text in the private-use range) and SVG. It runs again when the setting changes, with no reload. Reader can offer the same fonts.

How pages get the fonts (settled in R6)

  • Both apps the same way: the page script (page-font in apps/mobile/src/pagescripts/fonts.ts) gets the chosen font's files from the app as base64 and adds them with the FontFace API. A FontFace made from bytes fetches nothing, so a site's Content-Security-Policy font-src can't block it: it shows on GitHub as on Wikipedia, with no engine change and no URL scheme.
  • Only the chosen font goes in (Literata and Inter are about 180 KB each per style, pinned to text size on their optical size axis), read from the app once and kept. The family names the phone's font after the bundled one, so Hindi or Japanese text keeps the phone's font.
  • The core says which files a font needs and its family (browser/fonts.rs: site_font_face), and which font a page shows in (store.site_font(url): the site's own, else the one for all websites). scripts/subset-fonts.sh rebuilds the set.

Force dark

  • Android: our Chromium turns on Blink's own forced dark mode (force_dark_mode_enabled) per tab: BayTab.setForceDark, in android-engine-18. The strips behind the status bar and the bar follow it, since the page's own colours still read light.
  • iOS: WebKit has no forced dark mode. The first version is a page script: if the page already supports dark mode, ask for it; otherwise invert colours and turn images, video and canvas back. This is the riskiest part of the plan; ship it labelled Beta and test on a set list of sites.

Core API (sketch)

fn suggestions(&self, query, remote, current_url, now, scope: Option<SearchScope>) -> SuggestionResult
fn refresh_bangs(&self, http) / bang list kept in the core's data folder

// store: bookmarks
Action::SaveBookmark | MoveBookmark | UpdateBookmark | NewBookmarkFolder
fn bookmark_location(&self, url) -> Option<BookmarkLocation>   // space, folder path, id
fn bookmark_rows(&self, space_id, open: Vec<String>) -> Vec<BookmarkRow>  // flattened, with depth

// store: site settings
enum SiteFont { Original, System, Literata, Inter, Nunito, Charis, Lora }   // Original only per site
SiteSetting { …, font: Option<SiteFont>, fullscreen: bool, force_dark: bool, mini_player: Option<bool> }

Every new string goes in packages/mobile-core/strings/*.json. New fields read safely from older saved data (#[serde(default)]) and are added to is_default().

Decisions (settled)

D1 · What opens the bookmarks drawer
Settled (changed): a Bookmarks row in the page menu, and tapping the "Added to …" notice, which opens the drawer on that folder. A Bookmarks button in the bar's fourth slot was built and taken out: the bar stays at three buttons. No edge swipe, because swiping from the right edge would clash with swipe-to-go-forward.
D2 · Search finds bookmarks in every space
Settled: yes. The current space's bookmarks come first, then other spaces' with their space name shown ("Work · Trips"). Opening one from another space switches to that space and opens it there.
D3 · Switching space in the drawer switches the browser (changed after looking at how spaces switch)
Settled: yes. At first this was "the drawer only browses", but then the same gesture (swiping sideways over a tinted space with chips) would do different things in the drawer and the tab view. The rule is now "the space you see is the space you're in"; the save sheet is the only exception. Nothing is lost by switching: each space brings back its last tab.
D6 · How to switch spaces from a page
Settled: hold Tabs, slide to a space, lift. Lifting without sliding puts the column away; there is no Tabs menu. The Tabs button always shows the space, and a short pill appears after a switch. The tab view's sideways swipe follows the finger. See section 6c.
D4 · The shortcut row fills itself
Settled: automatic (pinned sites with a site search, then the most-visited ones), with nothing to set up. Editing the row is a later addition.
D5 · Fonts ship in both apps
Settled: Bay bundles one set of openly licensed fonts in both apps (Literata, Inter, Nunito, Charis, Lora), plus System, which uses each platform's own font. See section 7 for sizes and how pages get them.
