Implementation proposal · researched 26 October 2026 · plan only

Shared shaders.
Grain that actually shows.

Give Windows and Linux one WebGL2 backend in @bay/shaders, retain macOS Metal, and restore the fine, static grain associated with Arc and Ardia. Ship active effects first, then add Ardia's useful theme treatments.

This document selects the recommended options. Implementation begins after the desktop platform branches land. No shader implementation, benchmark result, commit, or deployment is claimed here.

Objective and current state

Keep one public component contract for WindowBackdrop, PowerUp, AreaLight, and EdgeLight. Windows and Linux share GLSL, color math, scheduling, and fallback code. macOS keeps its Metal renderer and native window materials. Visible grain must work in solid and glass themes without becoming an idle animation.

Ardia and Arc as references

Ardia was refreshed and inspected at 15011c4a858abfa113048a116a29457183205c06. Keep it as a source-backed design and engineering reference, with the demo and native application distinguished.

  • Demo GLSL manually expresses the backdrop, PowerUp, and halo. Vite aliases route @ardia/shaders to demo shims. This is not automatic Metal transpilation or an established production Windows/Linux shader backend.
  • GLSurface uses WebGL2, low-power context attributes, premultiplied alpha, sRGB output, resource cleanup, and context restoration. Its clock and sizing cover shared scheduling, hidden documents, on-screen observation, and fractional DPR changes. Reuse these approaches, adding Bay's host visibility and live accessibility changes.
  • Native gradient layers, seeded texture tiles, and ThemeSwatch offer useful additions. The native source has grain, sand, denim, and tweed. Its demo shader wrapper does not implement that full native theme contract.
  • Current Ardia exports backdrop, PowerUp, and ThemeSwatch. Its README says the older AreaLight reconstruction was removed. Bay's retained Metal AreaLight and EdgeLight are the reference for those ports.
  • Arc is a visual reference for fine texture, restrained color fields, and readable chrome. Arc's source is not public; this plan makes no claim about its exact grain algorithm. Ardia's names and comments describe its reconstruction, not proof of Arc's implementation.

Source and attribution decision

Ardia's NOTICE and license section distinguish its Apache-2.0 own source from the GPL-3.0 distributed app/engine. Bay's NOTICE declares Apache-2.0. Adapt only the relevant own-source files, retain notices and Apache license, and record paths, SHA, and modifications in packages/shaders/PROVENANCE.md plus Bay's NOTICE where material is copied. Do not import Ardia's engine or app distribution.

Bay shader comments already attribute noise/hash or SDF approaches to Dave Hoskins and Inigo Quilez; Ardia documents Dia-derived reconstruction. Preserve those attributions. Before copying an additional third-party snippet, establish its file-specific source and license. If that provenance cannot be established, implement the required math independently with documented references or keep that addition deferred. Repository-level Apache metadata alone is not evidence for every upstream snippet.

Chosen decisions

Question Selected approach
Backend WebGL2 and GLSL ES 3.00 on Windows/Linux; existing Metal on macOS. Handwritten ports, no translation pipeline, WebGL1 compatibility layer, WebGPU, Three.js, or new rendering framework.
Public API Keep existing props and defaults. Move shared public types and DIA_SPECTRUM into shared modules used by both entries; retain native array adapters. Use @bay/platform for view compatibility. Keep DOM code out of native resolution.
Static rendering One lazy WebGL2 producer per document renders static backdrops and copies each completed draw immediately to the component's retained 2D canvas. Redraw only on inputs, CSS size, DPR, or restoration. Coalesce editor updates to one draw per frame and retain only its latest request. No full-frame screenshot cache in v1; cache parsed colors, uniforms, and small grain tiles with bounded keys. Measure the copy cost before enabling broadly.
Animated rendering Direct WebGL canvases for finite animations, maximum two animated contexts per document. PowerUp and its optional halo use one effect-owned context with separate passes/regions. A third animation uses its CSS fallback. Share one RAF scheduler; do not copy full-screen animated buffers through the static producer.
Resource sharing Share source strings, CPU color data, and scheduling. Cache programs and uniform locations only inside their owning context. Never reuse a WebGLProgram, texture, or uniform location across contexts or windows. Static service plus two animation slots bounds steady WebGL contexts at three per document.
Capabilities vibrancy and windowBackdrop describe native host treatments, independent of shader support. Extend capabilitiesFor with an optional injected WebGL2 probe result; os.web.ts supplies it and pure tests fake it. Keep shaders true for working native modules or a successful web probe. Probe one tiny canvas lazily and release it. Every effect still handles real allocation/compile failures locally; do not gate its CSS fallback on this boolean.
Failure behavior Always render a usable CSS base first. Use OKLab CSS gradients when supported, ordinary gradients otherwise, plus a deterministic noise tile. Use static radial glows/outlines for decorative light fallbacks. A disabled/blocked GPU, compile failure, or lost context must never blank chrome or block onboarding.
Quality Cap effective DPR at 2 and each render target at 8 megapixels, preserving aspect ratio and respecting GL size limits. Grain cells remain in CSS pixels when resolution is capped. No continuous adaptive quality loop in v1. The low-power context hint is a request, not a guarantee.

Grain contract and visible defaults

  • Preserve grainOpacity as strength and grainScale as logical points/CSS pixels per cell. Keep the native package defaults 0.09 and 1. Clamp opacity to 0–1, clamp scale to at least 0.25, and reject nonfinite geometry.
  • Set Bay's dark preset default to 0.09 and retain light 0.05. Retain saved custom mapping grain × 0.12 and explicit caller overrides. These are selected starting values to validate in the fixture matrix, not measured perceptual thresholds.
  • Use the existing static multiply treatment for the solid gradient. Compute cell = floor(topLeftCssPosition / grainScale), independently of framebuffer pixels. Use a fixed seed of zero; no time uniform, random mount seed, or grain flicker. AreaLight.noiseSeed retains its separate effect-specific meaning.
  • For native glass and Windows Mica, layer equivalent static darkening noise above the tint and below content. A black-alpha noise layer expresses the same multiply attenuation without sampling the desktop. Do not cover a real native backdrop with an opaque gradient. On hosts without native treatment, use the themed solid gradient.
  • Honor tintLightness in web tint-gradient generation. Match the native glass tint treatment rather than applying a second tint to already tinted solid windowTint colors.
  • Change the dial's internal sample from value × 0.45 to the same shared value × 0.12 mapping as the window. Add a labeled enlarged grain inspection sample in development tooling so it remains easy to inspect without misleading the product preview.

Lifecycle rules

Use ResizeObserver, CSS dimensions, device-pixel sizing where available, and a DPR media-query listener. Ignore zero-size/offscreen targets. Pause animated drawing for hidden documents, offscreen views, minimized/occluded host windows when the bridge reports them, and window blur; pause effect time instead of catching up after a long gap. CSS opacity and transforms handle space transitions without rerendering static grain.

Listen to reduced-motion changes while mounted. Suppress decorative PowerUp/halo motion, settle AreaLight and EdgeLight to defined still frames, and remove them in forced-colors/high-contrast mode. Keep grain at zero under contrast settings; reuse Bay's highContrast.ts theme behavior and also cover previews outside that theme path.

On webglcontextlost, call event.preventDefault() to allow restoration, stop dependent scheduling, and show the CSS base. On restoration, recreate every program, texture, framebuffer, extension, and uniform location, then redraw current inputs without replaying finished animations. Release resources, observers, subscriptions, and pending requests on unmount. Do not retry failed allocations in a render loop. These requirements follow the Khronos context-loss rules, which are a work-in-progress specification.

Implementation sequence and exact files

Responsibilities below describe future implementation ownership. This research artifact changes no tracked source. Steps 1–5 complete shared shader parity; step 6 adds the selected Ardia treatments after those gates pass.

01

Integrate the platform prerequisites and capture a baseline

Depend on the Windows/Linux platform stack landing on main, including packages/platform, scripts/web.mjs, Expo web dependencies, browser bootstrap, and the shader web entry. Preserve both branch owners' conflict resolutions.

Verify packages/shaders/package.json browser/react-native/default conditions, apps/browser/metro.config.js with BAY_WEB=1, and apps/browser/tsconfig.web.json module suffixes. Windows and Linux scripts/*/build-app.py already call the same @bay/browser build:web on the inspected Linux branch. Do not create a parallel Vite app or demo-only alias.

Capture before images and traces for the actual callers on macOS, Windows, and Linux. Record build SHA, hardware/GPU/driver, host Chromium version, dimensions, DPR, theme, and accessibility flags. Extend the existing apps/browser/scripts/perf/ tooling with a dedicated shader runner; its current React/native benchmarks are not shader GPU measurements.

02

Unify contracts and build the web renderer

Update packages/shaders/src/types.ts, src/index.tsx, and src/index.web.tsx; add src/constants.ts. Remove duplicate public prop declarations while preserving native adapter prop names and export compatibility.

Add src/web/surface.ts, staticRenderer.ts, clock.ts, ShaderView.tsx, colors.ts, uniforms.ts, fallbacks.tsx, and sources/{common,backdrop,powerUp,areaLight,edgeLight}.ts. Use typed uniform descriptors and explicit premultiplied sRGB output. Implement top-left UVs, per-context program caches, allocation limits, fallback states, and lifecycle rules before effect ports.

Update packages/platform/src/capabilities.ts and os.web.ts; add shaderSupport.web.ts for the bounded probe and test it independently. Keep platform free of imports from @bay/shaders. Extend package scripts, tsconfig.json, and add tsconfig.web.json if needed so both native and DOM code typecheck under their correct conditions.

03

Restore backdrop grain end to end

Implement the OKLab backdrop and static grain from Bay's ios/WindowBackdropView.swift, with Ardia's GLSL as a porting reference. Add src/web/grain.ts for the deterministic fallback/glass tile and common cell rules.

In ios/WindowBackdropView.swift and ios/ShadersModule.swift, forward grain opacity/scale into a static layer on WindowTreatmentView as well as the Metal uniform path. Keep MetalSurface.swift and the macOS backend. Change defaults in apps/browser/src/lib/theme.ts and preview mapping in components/spaces/ThemeEditor.tsx. Check the current App, SpaceSwipe, LittleBayWindow, and Postcard callers without adding OS branches to them.

Finish this step when solid and glass paths expose clearly different zero/default/high grain states and resizing or dragging between monitors does not change logical cell size.

04

Restore the active PowerUp and halo

Port ios/PowerUpView.swift into src/web/sources/powerUp.ts and its uniform builder. Preserve palette selection, alpha, speed, origin, radius, optional halo, 24 CSS-pixel blur, and finite timing. Bay's current native limits are 3.75 seconds for the band and 2 seconds for the halo; preserve those semantics rather than extending duration by speed.

Use one animation context for the band/halo, with bounded intermediate targets for band blur so the halo is not blurred accidentally. Verify apps/browser/src/components/onboarding/Intro.tsx with its existing props. Handle live reduced motion, Skip/unmount, and failure fallbacks without changing onboarding navigation or music.

05

Complete the remaining exports with fidelity tests

Port Bay's ios/AreaLightView.swift and ios/EdgeLightView.swift into their GLSL modules. Preserve rounded emitter geometry, palette/falloff/lift/tilt/noiseSeed/intro/replay behavior for AreaLight; preserve rect, logo cutout, light endpoints, radius, color, delay, and duration for EdgeLight.

Translate Metal-specific selection, modulo, and reversed smoothstep behavior explicitly. Keep finite clocks and defined final frames. Test null/zero-area emitters and degenerate rectangles before drawing. These effects remain fixture-only until a separate product change supplies real callers.

06

Add the useful Ardia treatments

Acceptance tests and measurement gates

All figures below are proposed release gates. Establish and record the baseline in step 1; no measurements have been achieved by this plan.

Build and resolution

  • Run pnpm --filter @bay/shaders typecheck, pnpm --filter @bay/platform typecheck, pnpm --filter @bay/platform test, pnpm typecheck:web, and pnpm build:web after prerequisites land. Add @bay/shaders test:web for the new real-browser fixture runner.
  • Retain pnpm --filter @bay/shaders shaders:check under full Xcode and perform a macOS bundle/build smoke test. Metal checks do not validate GLSL.
  • Assert web bundles resolve index.web.tsx and contain no native shader manager calls. Assert macOS resolves the native entry and initializes no DOM/WebGL code. Run actual Windows and Linux host smoke tests, not only a browser demo.
  • If public native prop types move, check packages/platform/scripts/native-contracts.mjs extraction, regenerate src/nativeContracts.ts and windows/NativeContracts.g.h through existing scripts as required, and run pnpm --filter @bay/platform contracts:check. Do not hand-edit generated contracts.

Deterministic visual fixtures

Add packages/shaders/tests/fixtures.ts, tests/web/, and scripts/check-web-shaders.mjs. Reuse the repository's browser-test dependency if available; otherwise add one development-only browser driver with pnpm. Build the fixture through the real Metro web package path. Add fixed-time/debug controls, deterministic seed, backend identity, and frame counters. Reuse native MetalSurface.writeSnapshot and debug snapshot hooks for comparison.

  • Capture all four exports, PowerUp halo, and actual backdrop callers in light/dark, solid/glass, active/inactive, neutral/saturated colors, alpha 0/partial/1, and angle 0/90/135/150/180.
  • Exercise grain opacity 0/default/0.12/0.45 and scale 0.25/1/2/4 at DPR 1/1.25/1.5/2. Move across mixed-DPI monitors and change zoom without remounting. Confirm logical grain size, clipping, and top-left origin stay consistent.
  • Same renderer/build, seed, dimensions, and frozen time must yield the same fixture output. Across GPU/Metal/WebGL implementations, compare tolerances and perceptual structure instead of demanding identical noise hashes. For grain-disabled opaque gradient interiors, target per-channel mean absolute error at most 2/255 against the reference. Inspect grain contrast, average luminance shift, cell size, and seams separately.
  • For grain at zero, require zero residual texture. For default versus zero, require a nonzero texture residual and visible distinction in 1:1 crops. For higher values, require increasing texture contrast. Review ordinary window size as well as enlarged crops, without reducing text or focus-ring contrast.
  • Exercise real editor updates, paging, Postcard clipping, Little Bay, onboarding replay/Skip, and later swatch/texture selection. Snapshot animated effects at start, midpoint, and completion using injected time.

Failure and accessibility

  • Test unavailable WebGL2, GPU disabled/blocked, context allocation/compile/link failures, and context loss/restoration through WEBGL_lose_context. CSS chrome stays visible; restoration recreates resources and draws the latest theme without a reload.
  • Test mount/unmount 100 times, prop updates during restoration, hidden tab, minimized window, offscreen view, zero-size host, and multiple windows. Listener/context counts return to their steady baseline; no duplicate animation subscriptions remain.
  • Toggle reduced motion, prefers-contrast: more, and forced-colors: active while mounted. Decorative motion stops, contrast mode removes grain, and controls/navigation remain usable. Decorative canvases are hidden from assistive technology and never intercept pointers.

Performance budget

  • Record three matched runs on at least one Windows integrated GPU and one Linux integrated GPU; include Linux Wayland and X11 correctness checks. Keep CSS-only, current Metal, and WebGL results labeled separately.
  • Measure p50/p95 frame intervals, missed frames, main-thread draw/copy time, compile time, live contexts, target pixel bytes, and idle draw counters. GPU timer queries are optional and only reported when supported and not disjoint; missing GPU timing is not zero cost.
  • For 30 seconds after a static scene settles, require zero shader draws and no subscribed RAF loop. Require the same for hidden/minimized effects and after finite animation completion. Static redraw/copy occurs only after invalidation.
  • At 1920×1080 CSS pixels and DPR 1, target p95 total animation frame work within 16.7 ms on the selected integrated-GPU reference device. Target backdrop invalidation draw-plus-copy p95 below 8 ms after warmup, and no shader-caused main-thread task over 50 ms. Measure capped high-DPI targets separately.
  • Reject a rollout with more than a 10% regression in p95 interaction frame interval versus its matched CSS-only baseline, more than three steady WebGL contexts per document, or monotonically growing resource counts across the 100-cycle test. If a gate fails, retain the CSS rollout path and fix the responsible effect before expanding enablement. No automatic benchmarking or retry loop runs in production.

Rollout, dependencies, and stop criteria

  1. Land this plan-only HTML artifact on main. The parent owns review, commit, and push. Keep platform conflict work and product implementation out of that commit.
  2. After desktop platform integration, land shared contracts, renderer, fixtures, and fallback coverage behind a single development rollout switch, BAY_WEB_SHADERS=1. Propagate it through scripts/web.mjs; do not add a product settings panel.
  3. Enable backdrop/grain and native glass grain only after step 3's visual and static-idle checks pass. Then enable PowerUp, followed by fixture-tested AreaLight/EdgeLight. Use the CSS path as the immediate web rollback; keep native grain/default changes in their own reversible commit.
  4. After all parity gates pass on actual hosts, make WebGL2 the default supported web path and retain BAY_WEB_SHADERS=0 as a build-time rollback. Failure fallback remains automatic.
  5. Ship ThemeSwatch/multi-stop gradients, optional textures, then the preview-only rim as separate changes after parity. Texture persistence/sync compatibility is a dependency, not an unresolved decision.

Stop the initial implementation when all four existing exports render or fall back correctly on Windows/Linux, active callers have visible stable grain, native macOS materials/Metal still pass their checks, and visual/lifecycle/performance gates are recorded. Finish the selected additions only through their explicit dependencies above. Do not expand into a new rendering engine or unrelated browser features.

Explicitly deferred

WebGPU, Metal-to-GLSL generation, a unified native GPU backend, real Windows/Linux Liquid Glass or screen sampling, HDR/wide-gamut parity, animated grain, cursor-following lights, full-page postprocessing, particles, and unrelated browser roadmap changes. Ardia's icon-derived GlassGlow is also deferred because it depends on a broader icon/material pipeline; the scoped glass-rim treatment covers the useful immediate addition.
